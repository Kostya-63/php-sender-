## Context

Текущее приложение генерирует PDF-документ на сервере (mPDF), возвращает base64-строку на фронтенд, отображает PDF через `<iframe>`, а для отправки использует модальное окно с выбором канала (VK/Max/Email) и последующим POST-запросом на `/api/send`.

Пользователь хочет упростить этот процесс: вместо модального окна и серверной отправки — копировать PDF-файл напрямую в буфер обмена браузера.

**Ограничения:**
- Приложение работает в Windows (платформа: win32)
- Файл PDF хранится на фронтенде как base64-строка в переменной `pdfBase64`
- Clipboard API (`navigator.clipboard.write()`) поддерживается во всех современных браузерах (Chrome 86+, Firefox 113+, Safari 16.4+)

## Goals / Non-Goals

**Goals:**
- Удалить модальное окно отправки и весь связанный код (CSS, HTML, JS)
- Заменить кнопку «Отправить отчёт» на «Копировать в буфер»
- Копировать бинарные данные PDF в буфер как файл (`application/pdf`)
- Добавить визуальную обратную связь об успехе/ошибке

**Non-Goals:**
- Не изменять серверную логику отправки (эндпоинты `/api/send` остаются на случай будущего возврата)
- Не добавлять поддержку копирования в других форматах (только бинарный PDF)
- Не реализовывать fallback для браузеров без Clipboard API

## Decisions

### 1. Clipboard API vs. устаревший document.execCommand('copy')

**Decision**: Использовать `navigator.clipboard.write()` с `ClipboardItem`.

**Rationale**: `document.execCommand('copy')` устарел и не поддерживает копирование файлов. Clipboard API — современный стандарт, поддерживает `ClipboardItem` с произвольными MIME types, включая `application/pdf`.

**Alternative**: Fallback на создание временного Blob и `URL.createObjectURL` для скачивания. Отклонено, так как это не «копирование в буфер», а скачивание файла.

### 2. Передача PDF в ClipboardItem

**Decision**: Декодировать base64 в `Uint8Array` и создать `Blob` с MIME type `application/pdf`.

**Rationale**: `ClipboardItem` принимает `Blob` или `ArrayBuffer`. `Blob` с правильным MIME type — наиболее надёжный способ, который ОС (Windows) корректно интерпретирует как файл.

### 3. Имя файла

**Decision**: Использовать фиксированное имя `отчёт.pdf`.

**Rationale**: Текущий код уже использует это имя. Динамическое имя не требуется для MVP.

## Risks / Trade-offs

| Risk | Mitigation |
|------|------------|
| Clipboard API не поддерживается в старых браузерах | Приложение ориентировано на современные браузеры; в крайнем случае показать ошибку |
| Некоторые браузеры/ОС могут не корректно обрабатывать `application/pdf` в ClipboardItem | На Windows (основная платформа) Chrome/Edge корректно обрабатывают; тестировать на целевой ОС |
| Бэкенд-эндпоинты `/api/send` остаются неиспользуемыми | Оставлены как есть — не влияют на функциональность, могут быть удалены позже |
