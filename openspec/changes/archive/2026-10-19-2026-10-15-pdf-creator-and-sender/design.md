## Context

Монолитное PHP-приложение без фреймворка, работающее на порту 1100. Два этапа: сначала генерация и отображение PDF, затем отправка в мессенджер.

## Goals / Non-Goals

**Goals:**
- Простая структура без фреймворка, но с разделением на папки
- Генерация PDF через библиотеку mPDF
- Чистый AJAX-запрос без перезагрузки страницы
- Заглушка для отправки в мессенджер

**Non-Goals:**
- Аутентификация и авторизация
- Работа с несколькими типами документов
- Интеграция с конкретным мессенджером (этап 2)
- Сохранение PDF на диск (только в памяти)

## Decisions

### Решение 1: mPDF вместо DOMPDF или TCPDF
- **Выбор:** mPDF
- **Почему:** Лучшая поддержка UTF-8 (кириллица), современный, активно развивается
- **Альтернативы:** DOMPDF (плохой UTF-8), TCPDF (устаревший)

### Решение 2: Чистый PHP + AJAX без фреймворка
- **Выбор:** Без фреймворка
- **Почему:** Простота, минимум зависимостей, один серверный файл
- **Альтернативы:** Laravel (overkill для такого проекта)

### Решение 3: PDF в памяти (не на диск)
- **Выбор:** Возврат PDF через `output buffer` в браузер
- **Почему:** Не занимает место на сервере, проще архитектура
- **Альтернативы:** Сохранение на диск → отдача файла

### Решение 4: Структура проекта
```
app/
  controllers/   ← HTTP-логика
  services/      ← бизнес-логика
  views/         ← HTML/JS
public/
  index.php      ← точка входа
```

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| mPDF может не загрузиться при отсутствии composer | Документация по установке |
| Нет кэширования — PDF пересоздаётся каждый раз | На этапе 2 добавить кэш |
| Заглушка отправки в мессенджер | Чёткий интерфейс сервиса `MessengerService` |
