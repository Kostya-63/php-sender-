## Context

Первый этап реализовал генерацию PDF. Теперь нужно реализовать реальную отправку через 3 канала: VK, Max, Email.

## Goals / Non-Goals

**Goals:**
- Реальная отправка PDF через VK Bot API
- Реальная отправка PDF через Max API
- Реальная отправка PDF через Email (SMTP)
- Интерфейс выбора получателя и канала
- Единый интерфейс MessengerService для всех каналов

**Non-Goals:**
- Интеграция с Telegram, WhatsApp
- Статус доставки (read receipts)
- История отправленных отчётов
- Массовая рассылка

## Decisions

### Решение 1: Единый интерфейс MessengerService
- **Выбор:** Abstract MessengerService с методами send($pdf, $recipient)
- **Почему:** Единый API для всех каналов, легко добавлять новые
- **Альтернативы:** Отдельные контроллеры для каждого канала

### Решение 2: Конфигурация в config/messengers.php
- **Выбор:** PHP-файл с токенами и настройками
- **Почему:** Простота, не нужен .env парсер
- **Альтернативы:** .env файл, БД

### Решение 3: PHPMailer для Email
- **Выбор:** PHPMailer (composer package)
- **Почему:** Стандарт де-факто для PHP, поддержка SMTP, SSL/TLS
- **Альтернативы:** mail() (ненадёжно), SwiftMailer (устарел)

### Решение 4: Пагинация получателей
- **Выбор:** Загрузка всех получателей в сессию
- **Почему:** Простота, быстрый доступ к списку
- **Альтернативы:** AJAX-запрос при каждом открытии модалки

## Risks / Trade-offs

| Risk | Mitigation |
|------|-----------|
| Токен VK истекает через 1 год | Добавить предупреждение в UI |
| Max API требует паузу после загрузки | Реализовать retry-логику с увеличением интервала |
| SMTP может блокироваться | Поддержка нескольких SMTP-серверов |
| PDF > 25MB (VK лимит) | Проверка размера перед отправкой |

## Migration Plan

Нет миграции — добавление нового функционала.
